# 摄像头子模块 · 增量实现计划（P0→P1）

> 目标：把"摄像头/录像"做成 claw-platform 内的资产子模块（方向已确认：完整子模块、分期实现）。
> 依赖：《摄像头数据子系统技术方案 v1》（架构/存储/索引模型）、《分布式部署详细设计》、Phase 1 原型。
> 约束：本沙箱 Docker 守护不可用，代码按"任意 Docker 主机可运行"编写，验证需 Docker 主机 + 模拟摄像头。

---

## 0. 范围确认（已拍板）
- **数据模型**：Camera 作为 Asset 的子实体（asset_id 关联），状态枚举扩展 作业中/关闭/待作业/离线/故障。
- **双入口**：① 资产列表行内「历史回放」按钮（主入口）；② 顶级菜单「数据回放」（按资产编号检索）。
- **实时查看**：两入口均支持一键切 WebRTC 直播。
- **存储**：复用 v1（H.265 + 边缘热存 + 按类窗口 + 事件/稀疏帧永久 + 分级降冷）。
- **权限**：调看受 RBAC（`camera:view`）+ 资产/站点数据权限约束。

---

## 1. P0 — 最小闭环（可自验证）

**目的**：跑通"1 路相机 → 边缘录像 → 中心索引 → WebRTC 回放"，且**不依赖真实摄像头**。

### 1.1 基础设施（Phase 1 原型扩展）
在 `deploy/phase1/docker-compose.yml` 增资服务：
| 服务 | 镜像 | 作用 |
|------|------|------|
| `edge-media` | `ossrs/srs:5` | GB28181/RTSP 接入、本地录制、WebRTC/LL-HLS 出流 |
| `mock-camera` | `linuxserver/ffmpeg` + 循环样本 | 模拟一路 RTSP 相机，向 edge-media 推流（自验证关键） |
| `camera-recorder` | 轻量脚本/Node | 周期从 edge-media 切段 → 存 MinIO → 写 `video_segment` 索引（经后端 API） |

> 复用已有 pg-primary / MinIO；索引落 PostgreSQL（与 v1 设计一致，P0 不引时序集群）。

### 1.2 后端 `camera` 域（claw-platform/backend）
新建包 `com.claw.server.camera`：
- 实体：`Camera`（asset_id, camera_idx, protocol, resolution, status, stream_url…）
- 枚举：`CameraStatus`（WORKING/CLOSED/PENDING/OFFLINE/FAULT）
- 仓储：`CameraRepository`
- 服务：`CameraService`（列表/按资产查/取直播地址/列段/时间轴）
- 控制器：`CameraController`（REST，受 `@RequirePermission("camera:view")`）
  - `GET /api/v1/cameras?assetId=` 资产下相机列表（含状态）
  - `GET /api/v1/cameras/{id}/live` 返回 WebRTC/LL-HLS 播放地址
  - `GET /api/v1/cameras/{id}/segments?from&to` 历史段（含 object_key）
  - `GET /api/v1/cameras/{id}/timeline` 稀疏时间轴 + 事件标记
- Flyway：`V91__camera_tables.sql`（`camera_stream`/`video_segment`/`event_clip`/`sparse_frame`/`monitor_whitelist`/`retention_policy`，SQL 见 v1 §5）

### 1.3 前端（claw-platform/web，React+antd）
- 复用现有资产列表页，行内加「历史回放」按钮 → 打开回放抽屉（时间轴 + 播放器）。
- 播放器组件 `CameraPlayer.jsx`：封装 WebRTC(flv.js/hls.js)，直播/回放切换。
- 状态徽标：资产/相机显示 作业中/关闭/待作业。
- 权限：菜单项从 `permissions` 表读取（沿用现有 `menu:{navKey}` 机制）。

### 1.4 P0 验收（对应 v1 §14）
1. `mock-camera` 推流 → `edge-media` 接收成功。
2. `camera-recorder` 切段 → MinIO 有对象 + PostgreSQL 有 `video_segment` 行。
3. 前端资产列表出现该相机 + 状态；点「历史回放」可播放近期段。
4. 点「实时」可 WebRTC 直播（延迟 < 1s）。
5. `edge-media` 宕机 → 索引不丢，恢复后继续。

## 2. P1 — 双入口 + 状态 + 全量

- **独立「数据回放」菜单**：顶级菜单（permissions 表加 `navKey=camera-playback`），按资产编号检索 → 列出其相机 → 时间轴 + 直播。
- **状态机**：资产/相机状态 作业中/关闭/待作业 与现有资产生命周期对齐（参考 AssetStateMachine），状态变更写审计。
- **边缘 AI（事件留证）**：`edge-media` 接推理（越界/失联/烟火/入侵）→ 写 `event_clip`（永久）+ 触发告警。
- **稀疏时间轴**： recorder 每 N 秒抽帧 → `sparse_frame`（永久），支撑长程回溯。
- **分级降冷**：MinIO 生命周期（热→温→冷→回收），白名单资产原始永久。
- **成本看板**：聚合每 asset/station 存储字节，超预算告警（P1 末或 P2）。

## 3. 与现有系统对接点
| 现有 | 对接方式 |
|------|----------|
| Asset 模型 / 资产类别(SOLAR/VEHICLE/DRONE/STATION) | Camera 以 asset_id 关联；无人机/车辆/站务天然复用 |
| RBAC / 菜单权限 | `camera:view` 权限 + `camera-playback` 菜单 navKey |
| Phase 1 分布式 | 索引随 pg 流复制高可用；视频边缘存 + 索引 CDC；MinIO 异地归档 |
| 前端菜单体系 | 新增页面 + permissions 表菜单行（无前端拖拽，沿用后端持久化） |
