# 摄像头数据子系统技术方案 v1

> 范围：新能源资产（光伏/电池/车辆/无人机）及服务站运营的摄像头数据——
> 接入、边缘录像、中心索引、分级存储、直播/回放、成本治理、与 Phase 1 分布式部署的集成。
> 版本：v1（方案层，落地前需按真实规模参数回填成本模型）
> 关联文档：《分布式部署详细设计》《Phase1 数据库高可用与异地备份落地清单》《闭环审计与无人机适配方案》

---

## 1. 背景与目标

### 1.1 规模基线（参数化，需回填真实值）
| 参数 | 取值（示例/假设） | 说明 |
|------|------------------|------|
| 资产总数 N_asset | 3,000,000（几百万中值） | 需按实际校核 |
| 每资产摄像头均值 r_cam | 2.5 路 | 含 3-4 路及无人机/车辆/服务站运营 |
| 视频流总数 N_stream | ≈ 7,500,000 路 | N_asset × r_cam |
| 单路码率（720p 连续） | 2 Mbps | ≈ 0.25 MB/s，≈ 21 GB/天，≈ 7.9 TB/年 |
| 实时监控 | 全部资产 | 靠边缘 AI + 按需拉流，非人盯人 |

### 1.2 需求矛盾与决策（已与产品确认）
- **原始全量永久不可行**：7.5M 路全量原始永久 ≈ **59 EB/年新增**、年存储成本 ≈ **$58M（≈4.2 亿￥）**，且只增不减，属物理/经济边界，非工程可优化。
- **已采纳方案**：**永久索引 + 事件留证 + 近期原始窗口（到期回收）**，按资产类别分级留存。
- **关键定义**："实时监控" = 边缘 AI 持续分析 + 人类/后台按需拉流；不等于连续录制与全量永久存储。

### 1.3 目标
1. 每资产摄像头可"像直播一样"被即时调看（亚秒级延迟）。
2. 全量资产具备**永久可回溯**能力（稀疏时间轴 + 事件留证），成本可控。
3. 视频**永不 centralized**；中心仅存索引（CDC 聚合），与 Phase 1 范式一致。
4. 成本可观测、可设预算、超阈告警。

## 2. 总体架构（边缘优先 + 中心索引 + 分级存储）

```
资产摄像头 ──GB28181/ONVIF/RTSP──▶ 服务站边缘节点
  (光伏/车辆/无人机/站务)            │  媒体网关 SRS/ZLMediaKit
                                   │  本地 SSD 热存（按类窗口）
                                   │  边缘 AI（抽帧+事件检测）
                                   ▼
              两条上行：
  ① 实时取流(WebRTC/LL-HLS)  ──按需──▶  中心信令/调度 ──▶ 用户/管理端
  ② 索引/元数据(CDC)         ──常驻──▶  中心索引库(分片+时序)
                                   │
                                   ▼
              分级对象存储（热/温/冷/永久）
              · 热：边缘 SSD（按类窗口）
              · 温：OSS 标准层（7d）
              · 冷：归档层（≥90d，分钟级取回）
              · 永久层：事件高清片段 + 稀疏时间轴 + AI 摘要
```

复用 Phase 1 的 `pg-primary/pg-replica + MinIO` 形态承载分级对象存储与异地归档；
中心索引库因体量巨大，使用**独立时序/列存集群**（见 §5），不与交易库混部。

## 3. 接入协议

| 协议 | 适用 | 处理 |
|------|------|------|
| **GB/T 28181** | 国标安防摄像头（国内主流） | SRS 以 GB28181 平台模式接入，SIP 注册 + 目录 + 实时点播 |
| **ONVIF / RTSP** | 国际品牌/柬埔寨项目常见 | 边缘网关拉 RTSP → 转封装 |
| **WebRTC / SRT** | 无人机回传、弱网低延迟 | 直推边缘网关 |
| **RTMP** | 老旧设备推流 | 网关接收转协议 |

**接入规范**：
- 每个服务站部署边缘媒体网关，负责本区域摄像头接入与协议归一。
- 摄像头注册即写入 `camera_stream`（asset_id, station_id, camera_idx, protocol, resolution, status），纳入中心索引。
- 统一转封装为内部传输格式（WebRTC/LL-HLS 友好），下游消费不感知原始协议。

## 4. 边缘节点（服务站自治）

每服务站一个**边缘媒体节点**容器组（Docker Compose，复用 Phase 1 形态）：

| 组件 | 职责 |
|------|------|
| 媒体网关（SRS / ZLMediaKit） | 接入、协议转换、本地录制、WebRTC/LL-HLS 出流、SFU 一对多 |
| 本地录像（SSD） | 按资产类别的"近期原始窗口"热存（§6 留存策略） |
| 边缘 AI 推理（NPU/GPU 共享） | 抽帧 + 事件检测（越界/失联/烟火/入侵/车辆异常/无人机越界失联） |
| 索引代理 | 把 segment/event/frame 元数据经 CDC 上报中心；本地缓冲防抖 |

**原则**：像素不出站，除非被调看或有事件。边缘 AI 只把"标签/片段指针"上中心。

## 5. 中心索引数据模型

交易型元数据（小、强一致）落 **PostgreSQL**（可与 Phase 1 同库或独立实例）：

```sql
-- 摄像头流注册（强一致，量小）
CREATE TABLE camera_stream (
  stream_id     BIGSERIAL PRIMARY KEY,
  asset_id      BIGINT      NOT NULL,
  station_id    BIGINT      NOT NULL,
  camera_idx    INT         NOT NULL,          -- 同资产第几路
  protocol      VARCHAR(16),                  -- GB28181/RTSP/WebRTC/SRT
  resolution    VARCHAR(16),                  -- 720p/1080p/4k
  status        SMALLINT    DEFAULT 1,         -- 1在线 0离线
  created_at    TIMESTAMPTZ DEFAULT now(),
  UNIQUE (asset_id, camera_idx)
);

-- 高价值/合规白名单（后续可开）：其相关原始高清永久留存
CREATE TABLE monitor_whitelist (
  asset_id      BIGINT PRIMARY KEY,
  raw_permanent BOOLEAN DEFAULT true,
  window_days   INT     DEFAULT 365,
  reason        VARCHAR(128),
  granted_by    BIGINT,
  granted_at    TIMESTAMPTZ DEFAULT now()
);

-- 留存策略（按资产类别配置，驱动生命周期）
CREATE TABLE retention_policy (
  asset_class   VARCHAR(32) PRIMARY KEY,       -- VEHICLE/DRONE/STATION/SOLAR/...
  raw_window_days INT DEFAULT 30,             -- 近期原始窗口
  sparse_interval_sec INT DEFAULT 600,        -- 稀疏时间轴间隔
  event_permanent  BOOLEAN DEFAULT true
);
```

高体量时序索引（segment / event / frame）落 **独立时序/列存**（TimescaleDB 或 ClickHouse），按时间分片、冷热分离：

```sql
-- 视频段（近期窗口内的原始/转码片段，到期回收）
CREATE TABLE video_segment (
  stream_id   BIGINT,
  start_ts    TIMESTAMPTZ,
  end_ts      TIMESTAMPTZ,
  tier        SMALLINT,        -- 1热 2温 3冷
  object_key  TEXT,            -- 对象存储键
  size_bytes  BIGINT,
  event_tag   VARCHAR(32),
  PRIMARY KEY (stream_id, start_ts)
) /* TimescaleDB: time_bucket 分区 by start_ts */;

-- 事件高清片段（永久）
CREATE TABLE event_clip (
  event_id    BIGSERIAL PRIMARY KEY,
  stream_id   BIGINT,
  start_ts    TIMESTAMPTZ,
  end_ts      TIMESTAMPTZ,
  type        VARCHAR(32),     -- INTRUSION/LOST/SMOKE/COLLISION/...
  object_key  TEXT,
  permanent   BOOLEAN DEFAULT true,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 稀疏时间轴（永久，低存储）
CREATE TABLE sparse_frame (
  stream_id   BIGINT,
  ts          TIMESTAMPTZ,
  thumb_key   TEXT,            -- 缩略图对象键
  PRIMARY KEY (stream_id, ts)
);
```

> 索引量级：7.5M 路 × 日均数十~数百段 → 行数达百亿级，必须用分片 + 列存 + 冷热分层，否则中心库崩。

## 6. 分级存储与留存策略（生命周期）

| 层 | 位置 | 内容 | 留存 | 成本量级 |
|----|------|------|------|---------|
| **热** | 边缘 SSD | 近期原始窗口（按类） | VEHICLE/DRONE/STATION: 7~30d；SOLAR: 极短 | 本地盘，不上云 |
| **温** | OSS 标准层 | 窗口到期转存 / 活跃回放 | 7d | 中 |
| **冷** | OSS 归档层 | 长窗口/低频回放 | ≥90d，分钟级取回 | 低 |
| **永久** | OSS + 索引 | 事件高清片段 + 稀疏时间轴 + AI 摘要 | 永久 | 极小（仅事件/抽帧） |

**生命周期规则（示例，OSS 生命周期策略）**：
- 段对象 `raw/{station}/{stream}/*`：创建 30d 后转冷，再 90d 后删除（除非被事件引用）。
- 事件片段 `event/*`：永久，禁止过期。
- 稀疏帧 `sparse/*`：永久（低频层）。
- 白名单资产原始 `raw_whitelist/*`：按 `monitor_whitelist.window_days` 永久或长留。

**按类留存（核心优化）**：
- 实时监控重点（车辆/无人机/服务站运营）：较长原始窗口（7~30d），因是"直播+运营"主体。
- 静态资产（光伏板等）：仅稀疏时间轴 + 事件片段永久，原始不长期保留。
- 全局：边缘 AI 持续分析；原始视频仅在"被调看/有事件"时上中心。

**成本旋钮（给产品/老板的可调参数）**：
```
年原始存储 ≈ N_stream × f_monitored × window_days/365 × 7.9 TB
```
- `f_monitored`：带原始窗口的流占比（默认建议 ≤ 20%，即重点资产）。
- 例：7.5M × 20% × 30/365 × 7.9TB ≈ **97 PB/年**（对比全量 59 EB，降 600 倍）。
- 永久层（事件+稀疏）相对可忽略（事件约占流量 1~5%，稀疏帧为抽帧）。

## 7. 直播 / 回放链路

### 7.1 实时直播（"像直播一样"）
```
用户/管理端 ──请求 stream_id──▶ 中心信令
中心信令 ──路由──▶ 对应服务站边缘网关
边缘网关 ──WebRTC(亚秒)/LL-HLS──▶ 端
多观众：边缘 SFU 一对多，不重复占上行
```
- 默认 **WebRTC**（亚秒延迟，真·直播感）；弱网/兼容性回退 **LL-HLS**(~2-4s)。
- 中心只做信令与鉴权（复用 claw RBAC），不转发像素。

### 7.2 历史回放
- **近期窗口**：`video_segment` 查 object_key → 从 OSS（温/冷）经 HLS 直读/CDN 分发。
- **事件回放**：`event_clip` 直接取永久片段。
- **长程回溯**：`sparse_frame` 拼时间轴缩略图，点击跳转对应段。
- **秒开优化**：关键帧对齐 + ABR 多档位 + 边缘缓存热点段。

### 7.3 前端（复用 React 栈）
- 新增 `CameraLive.jsx`（WebRTC/flv.js/hls.js 播放器）+ `CameraTimeline.jsx`（稀疏帧时间轴 + 事件标记）。
- 权限：调看受 `camera:view` 权限约束（接入现有 RBAC）。

## 8. 中心能力

| 能力 | 实现 |
|------|------|
| 索引聚合（CDC） | 边缘索引代理 → 中心时序库；强一致元数据进 PostgreSQL |
| 信令/调度 | 轻量服务：流路由、会话管理、就近边缘选择 |
| 分片/扩容 | 时序库按 `stream_id` 哈希分片；热索引放缓存 |
| 成本看板 | 聚合每 asset/station/tier 的写入字节与流量，超预算告警 |
| 灾备 | 索引随 Phase 1 流复制/CDC 高可用；视频靠异地归档兜底 |

---

## 9. 成本治理

- **预算护栏**：每 station/asset_class 设月度存储预算；超阈自动降级（缩短窗口/降抽帧频率）并告警。
- **白名单审批**：高价值原始永久需审批（合规留痕），防止"全量永久"借白名单复活。
- **看板指标**：原始留存占比 `f_monitored`、各层字节数、事件/抽帧比、单位资产成本。

---

## 10. 合规与隐私

- 摄像头涉人脸/场所，属个人信息：留存须有合法依据，留存期限法定/约定上限。
- 调看受 RBAC 约束（`camera:view` + 资产/站点数据权限），全量审计日志（谁、何时、看哪路）。
- 永久留存仅限"事件留证 + 稀疏时间轴 + 白名单审批"，不默认全量。

## 11. 与 Phase 1 分布式部署的集成点

| Phase 1 能力 | 摄像头子系统复用方式 |
|--------------|---------------------|
| pg-primary/replica + 流复制 | 承载交易型元数据（camera_stream/whitelist/retention_policy）高可用 |
| MinIO / OSS 归档 | 分级对象存储后端 + 异地归档兜底 |
| 边缘自治 + 中心 CDC | 视频边缘存 + 索引 CDC 进中心，范式一致 |
| 灾备演练 | 索引库纳入 failover/PITR 演练 |

**不混部**：高体量 segment/event/frame 索引用独立时序集群，避免拖垮交易库。

## 12. 落地路线（分阶段）

| 阶段 | 目标 | 交付 |
|------|------|------|
| **P0 原型** | 跑通最小闭环 | Phase 1 加 `edge-media` 服务（SRS + MinIO + 索引表）：1 路相机→边缘录像→中心索引→WebRTC 回放 |
| **P1 试点** | 单服务站多路 | 边缘 AI 事件检测 + 分级存储生命周期 + 回放时间轴 |
| **P2 规模** | 中心索引分片 + 成本看板 | 时序/列存集群、信令调度、预算护栏 |
| **P3 全域** | 多区域 + 异地归档 | 按 Phase 1 Phase2/3 边缘自治 + 中心聚合 |

## 13. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 全量原始永久成本失控 | 按类留存 + f_monitored 护栏 + 白名单审批 |
| 中心索引库体量爆炸 | 独立时序集群 + 分片 + 冷热分层 |
| 边缘故障丢近期视频 | 边缘本地缓冲 + 中心索引冗余 + 异地归档 |
| 直播延迟/卡顿 | WebRTC + 边缘 SFU + ABR + CDN |
| 合规风险 | RBAC + 审计 + 留存期限上限 |
| 跨协议接入复杂 | 边缘网关协议归一，下游只认内部格式 |

## 14. 验收标准（P0 原型）

1. 一路 RTSP/模拟相机接入边缘网关，本地 SSD 录像成功。
2. 中心索引库出现对应 `video_segment` / `sparse_frame` 记录。
3. 浏览器 WebRTC 调看该路，延迟 < 1s。
4. 历史回放可从 OSS 拉取片段播放。
5. 触发模拟事件 → 生成永久 `event_clip` 并可回放。
6. 边缘节点宕机 → 中心索引不丢，恢复后继续上报。

## 15. 待产品回填的参数（决定成本与容量）

- 码率档位（720p/1080p/4k 分布）
